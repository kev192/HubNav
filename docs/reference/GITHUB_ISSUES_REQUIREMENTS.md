## 2. 产品基线与规划原则

### 2.1 当前能力基线

以下是实现规划必须复用的现有能力，不是本轮新增需求：

- 分类最多两层，已有分类树选择器；分类表单可编辑父分类、标题、图标和私密属性。
- 首页已有登录态操作入口、书签编辑、分类分组、同级排序和跨分类整理会话。
- 跨分类整理通过统一草稿保存，后端接口为 `/api/bookmarks/reorganize`；状态冲突会返回冲突错误并要求刷新。
- 后台已有书签搜索、按页展示、跨页批量选择、批量删除和不落盘排序。
- 备份页已有按分类选择导出，选择二级分类时会补齐必要的一级父分类；导入支持追加合并和覆盖。
- 卡片尺寸设置当前 `card_size.width` 的有效范围为 80—400 px；详情卡片和极简卡片在网格中还有各自的布局最小值。
- 首页导航、搜索分组和分类标题已经使用不同显示场景的图标尺寸；目前没有按分类层级持久化字体和图标尺寸的设置。

相关源码参考：`src/views/Home.svelte`、`src/components/CategorySection.svelte`、`src/components/HomeCategoryScope.svelte`、`src/components/admin/BookmarkListPanel.svelte`、`src/components/BackupPanel.svelte`、`src/lib/sortableList.ts`、`worker/routes/bookmarks.ts`、`shared/types.ts`。

### 2.2 PC / 移动端共同原则

1. **登录边界一致：** #11 的首页新增分类入口仅在管理员登录态展示；匿名用户不看到管理操作，也不能通过前端入口绕过鉴权。
2. **数据规则一致：** PC 和移动端使用同一分类层级、书签归属、排序保存和权限规则，不为移动端建立另一套数据语义。
3. **可取消、可恢复：** 排序、批量移动和编辑都先形成可见草稿或待确认状态；保存失败时保留错误原因并恢复或重新拉取服务端数据。
4. **触控优先的替代操作：** 移动端不能把鼠标悬停、右键或精确拖拽作为唯一入口；无法稳定拖动时必须提供按钮、菜单或表单替代路径。
5. **窄屏不溢出：** 操作按钮允许只显示图标但必须保留可访问名称；弹层、下拉树、批量工具栏和错误提示不得超出视口。
6. **不以视觉默认值替代语义：** 分类路径、当前分类、高亮状态、选中数量和保存状态都必须有文本或可访问属性表达。

### 2.3 端侧规划断点

| 场景 | PC 规划 | 移动端规划 |
| --- | --- | --- |
| 首页分类操作 | 标题右侧或操作组内显示文字按钮；空间不足时允许收纳到操作菜单。 | 使用紧凑图标按钮或“更多操作”菜单，按钮保持触控尺寸和可访问名称。 |
| 分类选择 | 可展开树、键盘导航、路径清晰。 | 全宽或底部弹层树，支持滚动、展开、当前项高亮和明确关闭。 |
| 拖动排序 | 鼠标拖放、拖放目标高亮、空分类可接收。 | 优先提供“移动到分类”操作；若实现触控拖动，必须同时保留非拖动替代路径。 |
| 批量操作 | 表格勾选、跨页选择、顶部批量工具栏。 | 卡片/表格行勾选，底部或顶部吸附批量工具栏，目标分类选择使用弹层。 |
| 卡片尺寸 | 设置页实时预览多列、长标题和描述。 | 以单列/双列和最窄可用宽度验证，不允许设置值破坏点击区域或文字可读性。 |

## 4. 详细需求与 UI 规划

### R-01：一级分类到二级分类的书签移动与排序

**云端已明确的问题**：当前跨分类排序无法从主分类拖动到子分类；反馈认为“从主分类向子分类的移动”是跨分类拖动的主要使用场景。

**建议交互方案**

- PC 首页进入“排序”会话后，一级分类和其二级分类都属于同一个拖放组；一级分类网格、二级分类网格以及空分类都可作为目标。
- 拖动卡片经过目标分类时，目标区域显示明确的分类名和接收态；保存前只修改本地草稿，不立即写库。
- 保存时同时提交书签的新 `category_id` 和每个受影响分类的完整顺序；取消时恢复进入排序会话前的顺序。
- 服务端发现分类或书签集合已变化时返回冲突，前端提示“数据已变化，请刷新后重试”，不得以成功提示覆盖冲突。
- 移动端不把长按拖动作为唯一方案。首选在书签操作菜单中提供“移动到分类”，复用同一分类树和保存规则；若后续增加触控拖动，仍保留该入口。

**PC 验收标准**

- 可从一级分类拖入同一父级下的二级分类，也可拖入其他一级或二级分类；空目标分类可接收。
- 保存后书签分类归属、目标分类内顺序和后台列表分类路径均正确，刷新后不丢失。
- 拖动过程中不触发书签打开；取消不产生服务端写入。
- 过期数据保存失败时能看到错误，服务端数据重新加载后不保留错误草稿。

**移动端验收标准（建议补充）**

- 不依赖 hover、右键或不可发现的拖动手势即可完成跨分类移动。
- 分类树可滚动、可关闭，目标分类路径和当前选择清晰；保存成功或失败均有反馈。
- 若支持触控拖动，不能遮挡滚动和点击书签，也不能移除“移动到分类”替代入口。

**待确认**：Issue 未说明浏览器、源/目标结构、失败表现、同父/跨父分类和移动端范围；实现前应补充至少一个 PC 回归场景和一个移动端操作方案。

### R-02：首页新建子分类入口

**云端已明确的需求**：登录状态下，在主分类的新建/排序操作附近增加新建子分类功能；原反馈标记为“感觉必要”。

**建议交互方案**

- 入口绑定当前一级分类，点击后直接打开已有分类编辑弹层的“新建”模式，并预填当前一级分类为 `parent_id`。
- PC 在一级分类标题操作组中显示“新建子分类”文字按钮；操作组拥挤时可收纳为带 aria-label 的菜单项。
- 移动端在一级分类标题的更多菜单中放置同名操作，菜单关闭后打开全宽或接近全宽的分类弹层。
- 成功后关闭弹层、刷新或局部更新分类树，并将新分类纳入当前一级分类的子分类范围；失败时保留表单内容和错误信息。
- 新建入口只对登录管理员展示；匿名首页和经常访问区域不显示管理按钮。

**验收标准**

- 从某一级分类进入新建子分类时，父分类已正确选中，不能误创建为一级分类。
- 取消不产生写入；成功后新分类标题、图标、父子关系和排序可在首页及后台看到。
- PC 和移动端入口均可发现、可键盘/触控操作，弹层不被底部或侧边导航遮挡。

**待确认**：是否允许在该流程中更换父分类；新建成功后是否自动滚动到新分类、自动选中子分类或保持当前视图。

### R-03：首页新增主分类入口

**云端已明确的需求**：在“经常访问”区域右侧增加新增主分类入口；原反馈标记为“感觉可选”，优先级低于 R-02。

**建议交互方案**

- PC 在“经常访问”标题右侧显示“新增主分类”；若该区域关闭或为空，将入口放在首页标题/主分类区域的登录态操作菜单中，避免入口随区域消失。
- 移动端使用经常访问标题栏的加号或更多菜单；区域为空时仍保留标题栏操作，不使用悬浮在卡片上的小按钮。
- 打开已有分类新建弹层，`parent_id` 默认为“无上级分类”；不复用 R-02 的当前父分类上下文。
- 成功后将新主分类加入首页分类树和导航；是否自动滚动到新分类需按确认结果实现。

**验收标准**

- 只有登录管理员看到入口；匿名用户的经常访问布局不因该入口产生空白占位。
- 创建结果是一级分类，父分类为空；不会因为从某个子分类上下文进入而意外创建为子分类。
- 关闭、保存失败和窄屏折叠均有明确状态，不发生重复提交。

**待确认**：经常访问区域关闭、无数据、仅一列或移动端时的具体放置；该可选入口是否与 R-02 同轮实现。

### R-04：首页编辑书签时定位当前分类

**云端已明确的需求**：在首页编辑书签，打开分类下拉列表后直接定位到书签当前分类，避免从列表顶部重新查找。

**建议交互方案**

- 打开编辑弹层时，将书签现有 `category_id` 传入分类树选择器；分类树根据完整路径展开父级并高亮当前项。
- “定位”只改变滚动、展开和高亮，不改变书签分类值；用户必须主动选择后才修改分类。
- PC 分类树支持键盘焦点移动，当前项进入可视区域；移动端弹层打开后自动滚动当前项到可视区域，并显示完整路径。
- 分类被删除或当前用户不可见时，显示“当前分类不可用”状态，不静默改到第一个分类；保存前按现有表单规则阻止无效引用。

**验收标准**

- 编辑有二级分类书签时，打开选择器会展开对应一级分类并定位到该二级分类。
- 编辑一级分类书签时，一级项高亮；打开和关闭选择器不会改变值。
- PC 键盘和移动端触控都能看到焦点/选中态；长分类列表不要求用户从顶部手动寻找。
- 保存仍使用现有分类引用校验，不能因“自动定位”绕过权限或层级限制。

**待确认**：定位是否仅滚动并高亮，还是需要自动展开父级（建议自动展开）；新建分类后是否自动选中；异常分类数据的具体提示文案。

### R-05：后台批量移动书签

**云端已明确的问题与方向**：新建分类或子分类后，逐个编辑书签修改分类很繁琐；希望在书签管理页查找、勾选多个书签并批量移动。

**建议交互方案**

- 复用现有搜索、分页和跨页选择：列表顶部显示“已选 N 项”，用户可选择当前页或继续跨页选择。
- 选中后显示“移动到分类”批量操作；目标选择器显示完整路径，例如“一级分类 / 二级分类”，并排除无效目标。
- PC 使用表格顶部批量工具栏和确认弹层；移动端使用吸附底部工具栏，目标分类使用全屏或底部弹层。
- 建议默认将书签追加到目标分类末尾，并按用户原有全局顺序处理；移动成功后清空选择、回到稳定页码并刷新分类路径。
- 建议服务端以一次受保护的批量操作完成归属更新和目标排序；集合校验失败时整体失败并返回冲突，不产生部分成功。
- 私密书签和私密分类继续遵循管理员权限；目标分类不存在、越权或跨层级非法时拒绝整批请求。

**PC / 移动端验收标准**

- 可在搜索结果和不同分页中保留选择，批量工具栏准确显示数量；取消选择不会改数据。
- 目标分类树显示完整路径、当前选项和禁用项原因；确认前能看到移动数量与目标。
- 成功后所有选中书签归属一致、顺序规则一致、列表路径更新；失败时不出现“部分成功”的误导提示。
- 移动端工具栏不遮挡列表操作，目标弹层可返回和关闭；PC 键盘可完成选择、打开目标和确认。

**待确认**：是否保留跨页选择；追加末尾、保持原顺序或指定位置；整体回滚还是逐项结果；私密数据在筛选和目标树中的显示边界。建议首版采用跨页选择、追加目标末尾、整体原子失败。

### R-06：分类和子分类字体、图标大小

**云端已明确的需求**：提供更改分类或者子分类字体和图标大小的功能。

**建议产品方案**

- 首版按层级提供全局设置：一级分类标题字体/图标大小、二级分类标题字体/图标大小；不立即引入每个分类独立覆盖，避免设置面板和数据模型膨胀。
- 设置作用于首页分类标题、首页二级分类标签、左侧/顶部导航和搜索分组；后台分类表格可保持紧凑固定尺寸，仅在预览中展示效果。
- 建议设置页使用两个层级分组，每组包含字号和图标尺寸数值控件，并提供实时预览；数值显示单位、最小/最大范围和移动端缩放说明。
- PC 预览展示长标题、无图标、图片图标和多子分类；移动端预览展示窄宽度、换行/省略、横向标签滚动和抽屉导航。
- 建议使用 CSS 变量或统一派生值传递到各显示场景，不在每个组件内复制一套硬编码比例。

**验收标准（待确认方案的基础）**

- 修改一级或二级设置后，所有列入作用域的显示场景同步更新，刷新后保持。
- 长标题、无图标、图片图标和两层分类在 PC、移动端均不发生不可读重叠、点击区域消失或横向页面溢出。
- 设置值越界、非数字和旧数据缺失时回退到安全默认值；保存失败不覆盖已保存设置。
- 一级和二级设置互不误写，且不会修改分类标题、图标内容或父子关系。

**待确认**：设置是全局、按层级还是每个分类独立；一级是否允许继承二级；准确作用域、范围、默认值、单位和移动端缩放规则。上述“按层级全局设置”是建议方案，不是云端已定决策。

### R-07：卡片最小宽度下限评估

**云端已明确的问题**：当前后台卡片最小宽度下限为 80，Issue 询问是否可以继续下调，或该限制是否有设计依据。

**当前实现基线**：设置表单和归一化逻辑目前将 `card_size.width` 限制在 80—400 px；详情卡片网格与极简卡片网格还有各自的布局最小值，不能只修改一个数字后宣称所有卡片均可用。

**建议 UI / 产品方案**

- 在设置控件旁说明“卡片最小宽度”单位为 px、影响范围和过小值的风险；保留实时预览，不用没有依据的文案声称 80 是唯一正确值。
- 预览至少覆盖详情卡片、极简卡片、长标题、长描述、图片/文字图标、双列和多列布局；同时显示 PC 宽屏、窄屏和移动端结果。
- 以可用性测试结果决定下限：点击区域、图标识别、标题可读性、描述截断、网格列数和横向溢出全部通过后，才调整设置范围。
- 若详情风格和极简风格需要不同下限，应在 UI 中明确显示，而不是让一个通用下限产生不可解释的布局结果。
- 移动端允许使用响应式列宽覆盖桌面设置，但不能使卡片小于触控和内容可读性的安全阈值。

**验收标准**

- 控件、共享类型、归一化逻辑、预览和首页实际网格使用同一套已确认范围。
- 任何允许保存的宽度在 PC 和移动端均能渲染完整卡片；不可接受的值在输入、保存和旧数据读取时一致拒绝或安全钳制。
- 详情风格的标题/描述、极简风格的图标/标题、点击区域和响应式列数均有回归截图或行为记录。
- 未确定目标下限前，不降低 80 的生产约束；可以先补充说明和预览验证。

**待确认**：80 的正式设计依据、目标下限、单位是否保持 px、两种卡片风格是否不同下限，以及移动端是否允许独立响应式规则。

### R-08：部分导出备份

**云端已明确的场景**：当用户维护两个或多个 CF-Navs 项目时，希望只导出某个分类及其书签，再同步到其他项目，而不是每次导出全部数据。

**当前能力对照**：仓库已有按分类选择导出、自动补齐二级分类所需一级父分类、书签过滤和设置处理；这属于“代码已存在、云端 Issue 仍 Open”的状态，不应再当作未实现功能重复规划。

**验收与同步要求**

- 选择一级分类时，导出其必要的子分类和对应书签；选择二级分类时，备份必须包含恢复层级所需的一级父分类，但不额外导出未选中的兄弟分类或书签。
- 导出结果应明确分类数、书签数和是否包含设置；不得覆盖目标项目未选择的内容。
- 导入目标项目时，覆盖/合并模式、重复分类、重复 URL、父子关系和管理员账号保护继续遵循 `docs/reference/API_CONTRACT.md`。
- PC 采用可展开分类树、全选/清空和导出反馈；移动端采用可滚动树和固定底部导出按钮，导出前显示汇总数量。
- 在确认源码行为、部署版本和 Issue 原作者预期一致后，维护者可在云端补充说明并决定关闭或继续保留 #9 的该项内容。

## 6. 建议的实现与验收顺序

这只是依赖关系建议，不是云端优先级承诺：

1. **R-01 跨分类边界修复**：先补齐一级→二级的 PC 回归场景，并确定移动端非拖动替代操作；它影响排序状态、数据冲突和用户核心路径。
2. **R-04 分类定位**：复用现有分类树选择器，先明确展开、高亮和异常分类规则。
3. **R-02 / R-03 首页入口**：在确认登录态、创建成功后的滚动与选中行为后接入现有分类弹层。
4. **R-05 批量移动**：确定跨页选择、排序、原子性和私密数据边界后，再设计 API 与后台工具栏。
5. **R-06 分类视觉属性**：先确定作用域和变量模型，再同时补设置表单、预览、首页、导航和搜索场景。
6. **R-07 卡片宽度**：以 PC/移动端真实预览和可用性回归决定是否下调，不先改生产范围。
7. **R-08 状态同步**：核对当前部署与导出行为后更新 #9 说明或关闭该项，不重复实现已有能力。
